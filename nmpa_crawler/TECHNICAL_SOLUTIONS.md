# NMPA爬虫技术解决方案文档

## 项目概述

本文档详细分析了NMPA（国家药品监督管理局）数据爬虫的技术挑战和解决方案。基于对9个主流开源项目的深度分析，我们提供了三种有效的技术方案来应对网站的反爬虫机制。

## 当前技术挑战

### 主要问题
1. **JS签名验证** - `sign or timestamp is empty` 错误
2. **反爬虫检测** - WebDriver和自动化工具检测
3. **IP封禁风险** - 高频请求导致访问限制
4. **动态参数** - 网站频繁更改加密算法

### 网站防护机制
- axios请求拦截器
- jsjiami.com.v6 混淆加密
- 时间戳签名验证
- 行为模式检测

## 技术方案对比

### 方案一：DrissionPage引擎 ⭐⭐⭐⭐⭐
**技术栈：** Python + DrissionPage

**优势：**
- 完全模拟真实用户操作
- 无需JS逆向工程
- 强大的反检测能力
- 维护成本低

**劣势：**
- 依赖浏览器环境
- 资源消耗较高
- 速度相对较慢

**适用场景：** 追求稳定性和低维护成本的项目

### 方案二：签名算法破解 ⭐⭐⭐⭐
**技术栈：** Python + HTTP请求 + 加密算法

**优势：**
- 直接HTTP请求，速度快
- 资源消耗低
- 支持高并发
- 可扩展性强

**劣势：**
- 需要持续维护签名算法
- 技术复杂度较高
- 网站算法变更时需要更新

**适用场景：** 追求性能和高并发的项目

### 方案三：undetected_selenium + stealth ⭐⭐⭐⭐
**技术栈：** Python + undetected_selenium + stealth.min.js

**优势：**
- 技术最先进
- 破解能力最强
- 适用于复杂反爬虫系统

**劣势：**
- 实现复杂度最高
- 维护成本高
- 依赖外部JS库

**适用场景：** 对技术要求极高的复杂项目

## 推荐方案：签名算法破解

基于项目需求和技术分析，我们选择**方案二：签名算法破解**作为主要解决方案。

### 技术架构

```
NMPA网站分析 → JS逆向工程 → 算法实现 → HTTP请求 → 数据解析
     ↓              ↓           ↓          ↓         ↓
  网络抓包      加密逻辑提取    签名生成    API调用    结构化输出
```

### 核心组件

1. **签名引擎 (sign_engine.py)**
   - 多版本算法支持
   - 自动算法检测
   - 动态参数生成

2. **HTTP客户端 (http_client.py)**
   - 会话管理
   - 重试机制
   - 代理支持

3. **数据解析器 (data_parser.py)**
   - JSON结构解析
   - 字段映射
   - 数据清洗

4. **配置管理 (config.py)**
   - 算法配置
   - 请求参数
   - 输出格式

## 技术细节

### 签名算法分析

基于网络抓包和JS分析，NMPA网站使用以下签名机制：

1. **基础签名 (V1)**
   ```
   sign = MD5(timestamp + params + secret_key)
   ```

2. **增强签名 (V2)**
   ```
   sign = HMAC-SHA256(secret_key, timestamp + params)
   ```

3. **复合签名 (V3)**
   ```
   encrypted = AES(secret_key, timestamp + params)
   sign = MD5(encrypted + nonce)
   ```

### 请求参数

{

## 性能优化

### 并发策略
- 线程池并发：3-10个并发任务
- 协程异步：高并发HTTP请求
- 请求限流：避免触发反爬虫

### 缓存机制
- itemId缓存：减少配置查询
- 签名缓存：相同参数复用
- 结果缓存：避免重复请求

### 错误处理
- 自动重试：指数退避算法
- 算法切换：失败时尝试其他算法
- 降级策略：回退到浏览器模式
